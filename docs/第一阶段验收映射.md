# 第一阶段验收映射

更新时间：2026-04-28

本文档基于当前仓库代码、自动化测试、Web/CLI 入口和 `TASKS.md` 现状，重新整理 FR-001 至 FR-015 与 AC-001 至 AC-018 的实现状态，并额外列出当前仍阻止生产上线的差距。

状态定义：

- 已完成：当前代码和测试已覆盖该功能的第一阶段核心行为。
- 部分完成：已有可用主链路，但仍缺关键子流程、真实外部接入或权限收口。
- 占位完成：只有模型、接口或流程边界，不等同于真实能力已经接入。
- 未开始：仓库内尚无对应实现闭环。
- 范围外：第一阶段明确不实现。

注意：

- 这里的“已完成”只表示当前第一阶段功能闭环已有代码和测试依据，不表示已经达到生产可用。
- 生产可用仍取决于统一鉴权、运行配置、真实识别、对象存储、迁移、审计、部署和恢复等系统性能力，见文末“生产就绪差距”。

## 生产就绪差距

以下问题会直接阻止当前仓库被描述为“可生产使用完成”：

1. 认证与权限未收口
   当前业务 API 仍大量依赖前端或调用方显式传入 `actor_id`、`member_id`、`submitter_id`；账号注册还允许直接选择管理员角色。
2. 生产账号初始化与注册策略未收口
   生产环境仍允许按当前基础注册接口自选角色，管理员初始化、邀请或审批链路尚未落地。
3. 真实识别链路仍未达到生产就绪
   当前已完成文本 PDF 的 PDF 文本提取，以及扫描 PDF / 图片直送 OpenAI 兼容多模态模型的结构化识别链路；但真实外部 Provider 联调、生产级队列治理和更完整的失败恢复仍未完成。
4. 文件访问权限仍未完全收口
   当前已支持 S3 兼容对象存储并通过后端导出接口读取产物，但统一 bearer 下载鉴权、原始材料外部访问边界和更细粒度导出授权测试仍未完成。
5. 数据库迁移演练仍不完整
   已引入 Alembic 基线并停止生产环境启动期 `create_all` 自动演进，但 PostgreSQL 实库演练、旧库迁移策略和后续增量 revision 经验仍未补齐。
6. 审计、可观测性和恢复基线缺失
   审计日志、请求 ID、指标、敏感信息脱敏、备份和恢复演练都还未完成。
7. 外部渠道适配未真正落地
   Telegram 和邮件仅是后端接入边界，不是完整的 Bot/Webhook/收件链路。
8. 导出交付链路仍未完全收口
   XLSX、统一 bearer 权限和更完整的导出下载授权仍未完成。
9. 上线演练仍未完成
   虽然已补齐 Docker Compose 部署基线和生产账号初始化说明，但上线前安全演练、备份恢复演练和真实外部依赖联调仍未完成。

## 当前结论

当前仓库已经具备第一阶段大量功能闭环，适合作为本地开发、测试和阶段性演示基础；但它仍不是生产就绪系统。

如果只按功能覆盖看，当前完成度较高的区域是：

- 任务基础管理、材料上传归档、发票校验、分摊、成员确认、CLI 主链路、缺失材料聚合和基础导出。

当前仍明显停留在“骨架/占位或未收口”阶段的区域是：

- 统一鉴权与权限收口；
- 真实 AI 识别流水线；
- 审计、部署与恢复；
- 真实 Telegram / 邮件外部接入；
- 真实 PDF 合并和导出交付。
