# 第一阶段验收映射

更新时间：2026-04-28

本文档按当前仓库代码和测试事实，整理需求文档第 15 节 AC-001 至 AC-018 的实现状态。状态定义如下：

- 已完成：当前代码和测试已满足该验收项的核心行为。
- 部分完成：已存在可复用基础能力，但仍缺少验收项要求的关键链路或约束。
- 未开始：仓库内尚无对应实现骨架，或只有非常间接的基础能力。

## 验收映射

| 验收项 | 当前状态 | 当前依据 | 主要缺口 |
|---|---|---|---|
| AC-001 报销任务创建 | 部分完成 | 已实现 `POST /api/tasks`，支持比赛名称、地点、时间、成员名单、费用类别、截止时间等字段；测试覆盖创建、查询、列表和基础字段校验，见 `src/trms_backend/api/tasks.py`、`src/trms_backend/domain/tasks.py`、`tests/test_tasks_api.py`。 | 尚无管理员认证与授权边界，也无“缺少成员名单时不能发布任务”的发布前门禁。 |
| AC-002 抬头税号配置 | 部分完成 | 任务模型和创建接口已要求 `invoice_title`、`tax_number`，并持久化到数据库，见 `src/trms_backend/domain/tasks.py`、`src/trms_backend/infrastructure/models.py`。 | 尚无全局配置模型，也无“新任务默认继承全局抬头和税号”能力。 |
| AC-003 多渠道提交 | 部分完成 | 材料提交接口统一接收 `web`、`cli`、`telegram`、`email` 四类 `channel`，并走同一材料仓储与重复文件检测逻辑，见 `src/trms_backend/api/materials.py`、`src/trms_backend/domain/materials.py`、`tests/test_materials_api.py`。 | 尚无真实 Web 页面、CLI 客户端、Telegram 接入器和邮件接入器；也无待归属材料流程。 |
| AC-004 CLI 提交 | 未开始 | 后端上传接口接受 `channel=cli`，可作为未来 CLI 复用基础。 | 仓库内尚无 CLI 工程、命令入口、认证绑定和上传交互。 |
| AC-005 CLI JSON 输出 | 未开始 | 当前无 CLI 实现。 | 尚无 `--json` 输出规范、schema version 和对应测试。 |
| AC-006 发票识别 | 未开始 | 当前只有人工录入发票接口 `POST /api/materials/{material_id}/invoice`，见 `src/trms_backend/api/invoices.py`。 | 尚无 OCR、PDF 解析、AI 识别任务、字段置信度和识别失败暴露。 |
| AC-007 抬头税号校验 | 已完成 | 创建发票时会生成 `invoice_title_match`、`invoice_tax_number_match` 校验结果；测试覆盖通过和不匹配路径，见 `src/trms_backend/domain/invoice_validation.py`、`tests/test_invoices_api.py`。 | 当前校验来源仍依赖人工录入发票字段，尚未接入自动识别链路。 |
| AC-008 大额支付记录校验 | 未开始 | 当前校验规则仅覆盖抬头、税号和重复发票。 | 尚无支付记录材料类型、附件关联模型和 `>= 1000` 金额规则。 |
| AC-009 附件完整性校验 | 未开始 | 当前无支付记录、比赛通知、行程单、订单截图等附件关联。 | 尚无按费用类型校验缺失材料的规则和提示结果。 |
| AC-010 费用分摊 | 已完成 | 已实现发票分摊替换与查询接口，要求分摊成员属于任务成员且金额合计等于发票金额；测试覆盖成功、金额不一致、成员越界和重复成员，见 `src/trms_backend/api/splits.py`、`src/trms_backend/domain/splits.py`、`tests/test_splits_api.py`。 | 尚无更高层的个人费用聚合视图和版本化确认链路。 |
| AC-011 成员确认 | 已完成 | 已实现成员对本人分摊明细确认或提出异议；测试覆盖确认、异议、异议原因必填和禁止确认他人分摊，见 `src/trms_backend/api/confirmations.py`、`src/trms_backend/domain/confirmations.py`、`tests/test_confirmations_api.py`。 | 当前确认粒度仍是单条分摊，不是需求文档中的“个人费用明细版本”模型。 |
| AC-012 管理员复核 | 未开始 | 任务状态枚举已包含 `reviewing`、`ready_to_export`，见 `src/trms_backend/domain/tasks.py`。 | 尚无管理员复核视图、最终确认门禁、人工更正和复核汇总接口。 |
| AC-013 导出汇总表 | 未开始 | 当前无导出模块。 | 尚无导出任务模型、汇总计算逻辑和文件输出。 |
| AC-014 导出 PDF | 未开始 | 当前无 PDF 合并或导出任务能力。 | 尚无打印顺序、损坏文件处理和导出状态模型。 |
| AC-015 权限隔离 | 部分完成 | 目前仅在成员确认接口上限制“成员只能确认自己的分摊”，见 `src/trms_backend/api/confirmations.py`、`tests/test_confirmations_api.py`。 | 尚无统一身份上下文、管理员权限、任务级数据隔离和导出访问控制。 |
| AC-016 重复发票检查 | 已完成 | 创建发票时会按同任务内发票号码生成 `invoice_number_unique` 校验结果；测试覆盖重复号码失败路径，见 `src/trms_backend/api/invoices.py`、`src/trms_backend/domain/invoice_validation.py`、`tests/test_invoices_api.py`。 | 当前仅覆盖发票号码重复，尚未与跨渠道重复文件 hash 检测联动展示。 |
| AC-017 缺失材料提醒 | 未开始 | 当前无缺失材料清单模型或聚合接口。 | 尚无按成员输出缺失材料结果，也无提醒记录或通知占位。 |
| AC-018 审计记录 | 未开始 | 当前数据库模型中尚无审计日志表。 | 尚无材料提交、金额更正、确认、导出等关键操作审计。 |

## 结论

当前后端已形成的最小闭环主要集中在以下验收项：

- AC-007 抬头税号校验
- AC-010 费用分摊
- AC-011 成员确认
- AC-016 重复发票检查

仍处于骨架或未开始状态的高优先级验收项主要包括：

- AC-002 抬头税号全局配置默认继承
- AC-008 大额支付记录校验
- AC-009 附件完整性校验
- AC-012 管理员复核
- AC-013 至 AC-014 导出能力
- AC-015 权限隔离
- AC-017 缺失材料提醒
- AC-018 审计记录
