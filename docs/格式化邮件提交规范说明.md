# 格式化邮件提交规范说明

更新时间：2026-04-28

## 当前目标

第一阶段邮件渠道只定义“格式化邮件如何被系统稳定解析并转入统一材料提交流程”的最小规范，不实现真实 IMAP 轮询、Webhook 收件、SMTP 回执或邮箱账号绑定代码。

本规范解决三件事：

1. 明确邮件主题里如何携带任务编号；
2. 明确正文元数据和附件的最小格式；
3. 明确格式错误时系统应返回或记录哪些稳定失败原因，避免静默丢件。

## 总体原则

1. 邮件渠道只是接入层，不在邮件解析器里复制材料归属、识别、校验或分摊规则。
2. 一封邮件只提交一种 `material_type`；如果成员要同时提交发票和支付记录，应拆成多封邮件。
3. 主题中的 `task_id` 是任务编号的权威来源；正文里的 `task_id` 仅用于冗余校验。
4. 发件人邮箱优先用于成员身份识别；若邮箱尚未绑定成员身份，但邮件格式合法，附件应进入待归属材料，而不是被静默丢弃。
5. 若邮件接入占位接口额外暴露 `resolved_member_id` 之类的“已解析身份”字段，该字段只能来自受信任入站器；匿名调用方自报的成员编号不得直接进入成员主链路。
6. 格式错误与业务归属失败要区分：
   - 格式错误：邮件本身不满足本规范，应返回或记录明确失败原因；
   - 归属失败：格式合法，但任务不存在、成员未绑定或成员不属于目标任务，应进入统一待归属或现有业务失败路径。

## 邮件主题格式

邮件主题必须满足以下两种格式之一。

推荐格式：

```text
[TRMS] task:<task_id>
```

兼容常见转发/回复标题的短格式：

```text
<task_id>Fw: 原始邮件标题
```

规则：

1. 推荐格式中，前缀 `[TRMS]` 必须区分大小写，作为邮件渠道专用标识。
2. 推荐格式中，`task:` 后必须跟非空任务编号，例如 `task-1`。
3. 短格式中，主题开头的第一个尖括号标识即任务邮件提交标识，例如 `<ccny2026>Fw: ...` 会解析为 `ccny2026`。
4. 主题中除任务标识外不再承载其他机器字段，避免把材料类型、成员编号等语义拆到多个位置。

示例：

```text
[TRMS] task:task-1
<ccny2026>Fw: 中国南方航空全电发票（全面数字化电子发票）
```

以下情况视为主题格式错误：

1. 既不是 `[TRMS] task:<task_id>`，也不是以 `<task_id>` 开头；
2. 推荐格式缺少 `task:` 段；
3. `task:` 后为空白；
4. 短格式尖括号内为空或包含空白；
5. 同一主题里出现多个 `task:` 段。

## 正文元数据格式

正文开头必须提供一个连续的键值对元数据块，每行一个字段，格式如下：

```text
material_type: invoice
submitter_id: member-1
task_id: task-1
note: 返程高铁电子客票

这里开始可以写自由文本说明，解析器忽略。
```

字段规则：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| `material_type` | 是 | 使用系统已支持的材料类型枚举，例如 `invoice`、`payment_record`、`competition_notice`、`itinerary`、`order_screenshot`、`other` |
| `submitter_id` | 否 | 当发件人邮箱已绑定成员身份时可省略；未绑定时可作为人工认领线索保存，但不直接绕过后续成员校验 |
| `task_id` | 否 | 冗余字段；若填写，必须与主题中的 `task_id` 完全一致 |
| `note` | 否 | 自由文本备注，供管理员后续查看，不参与业务规则判断 |

正文解析规则：

1. 只解析正文开头连续的 `key: value` 行；遇到首个空行后，后续内容视为普通说明文本。
2. 元数据键名统一使用小写下划线风格，当前只接受上表定义的键。
3. `material_type` 缺失、为空或不在支持枚举内，视为格式错误。
4. `task_id` 若存在且与主题不一致，视为格式错误。
5. `submitter_id` 即使存在，也不能替代发件人邮箱绑定直接获得成员权限；它只作为待归属线索或辅助排查字段。

## 附件规则

1. 一封邮件必须至少包含一个普通附件；只有正文、没有附件，视为格式错误。
2. 所有附件共享同一个 `material_type`。
3. 每个附件都必须带原始文件名；缺少文件名的附件视为单附件失败。
4. 附件的大小、内容类型和空文件校验，沿用统一材料上传规则，不在邮件渠道重复定义。
5. 邮件内联图片如果没有独立文件名或被标记为纯正文装饰资源，默认不作为提交材料。
6. 若一封邮件同时带有合法附件和非法附件，后续接入实现应沿用现有批量上传“部分成功”语义，逐附件返回或记录结果。

## 处理结果与失败原因

邮件接入器后续实现时，至少应稳定返回或记录以下失败原因：

| 失败码 | 场景 |
|---|---|
| `invalid_subject_prefix` | 主题既不是 `[TRMS] task:<task_id>`，也不是以 `<task_id>` 开头 |
| `missing_task_id` | 主题中没有合法 `task:` 段 |
| `duplicate_task_id_marker` | 主题中出现多个 `task:` 段 |
| `missing_metadata_block` | 正文开头没有任何可解析元数据 |
| `missing_material_type` | 正文没有 `material_type` |
| `unsupported_material_type` | `material_type` 不在支持枚举 |
| `task_id_mismatch` | 正文 `task_id` 与主题 `task_id` 不一致 |
| `missing_attachments` | 邮件没有可处理附件 |
| `attachment_missing_filename` | 某个附件缺少文件名 |

以下情况不属于“格式错误”，应进入既有业务边界：

1. `task_id` 格式合法，但系统内查不到该任务：
   - 进入待归属材料；
   - 记录 `task_id_hint=<subject task_id>`。
2. 发件人邮箱未绑定成员身份：
   - 进入待归属材料；
   - 记录 `submitter_id_hint=email:<sender>`；
   - 若正文提供了 `submitter_id`，可一并作为人工认领线索保存。
3. 发件人已绑定成员，但不属于目标任务：
   - 走统一成员权限校验失败路径；
   - 不由邮件接入器自定义特判。

## 示例

合法邮件示例：

主题：

```text
[TRMS] task:task-1
```

正文：

```text
material_type: invoice
submitter_id: member-1
note: 返程高铁电子客票和报销发票
```

附件：

1. `ticket.pdf`
2. `invoice.png`

该邮件的预期行为：

1. 解析器提取 `task_id=task-1`、`material_type=invoice`；
2. 若发件人邮箱已绑定且成员属于任务，则调用统一 `MaterialSubmissionService.submit_to_task`；
3. 若邮箱未绑定或任务暂不可归属，则调用统一 `submit_pending_assignment`，保留邮箱和可选 `submitter_id` 线索；
4. 每个附件分别返回成功、失败或重复结果，不静默吞错。

## 后续实现边界

下一步“增加邮件材料提交接入占位”任务应只做以下事情：

1. 解析本规范定义的主题、正文和附件；
2. 把格式错误映射为稳定失败码；
3. 把格式合法的附件转入既有统一材料提交服务；
4. 不在该任务中实现真实 IMAP 轮询、SMTP 回执、邮箱密码管理或完整邮箱绑定体系。
5. 若后续接入器要把“已解析成员身份”传入后端，必须通过受信任入站 token 或等价受控边界显式证明来源可信，不能让匿名请求直接指定。
