# 第一阶段范围边界说明

本文档用于固化 TRMS 第一阶段的非目标范围，避免把“财务录入前材料整理平台”误实现成“财务系统自动提交工具”。

## 当前定位

第一阶段系统只负责财务系统录入之前的工作：

1. 收集任务和成员材料。
2. 归档原始文件和结构化元数据。
3. 执行识别、校验、分摊、确认、复核和导出。
4. 为管理员生成可人工录入财务系统的整理结果。

第一阶段的完成边界是“生成可供人工处理的报销材料包”，不是“代替管理员向学校财务系统提交”。

## 明确不实现的能力

第一阶段不实现以下能力：

1. FR-011 Browser Use 或其他浏览器自动化方式录入学校财务系统。
2. 学校财务系统 API 对接。
3. 财务审批状态同步、回写和轮询。
4. CLI 直接驱动财务系统页面或接口提交。
5. 保存完整财务系统登录态、Cookie、账号密码或长期会话。
6. 自动完成最终财务提交或绕过管理员确认直接提交。
7. 替代学校财务处审批、自动判断所有政策合规性。
8. 成员银行卡、财务账号等财务系统内个人信息维护。

这些能力即使未来需要支持，也不属于当前第一阶段交付范围，当前代码路径不应为其引入主流程依赖或隐式兼容层。

## 与第一阶段已包含能力的边界

以下能力仍属于第一阶段范围，但只作为人工录入前的辅助结果：

1. 生成报销汇总表、成员明细表、发票明细表。
2. 生成缺失材料清单和财务填报草稿。
3. 合并打印 PDF 和整理线下投递材料。

这些输出的目标是帮助管理员人工录入和线下投递，不代表系统会自动登录、自动填表或自动点击提交。

## 后续阶段启用 Browser Use 的强制条件

如果后续阶段要评估 Browser Use 或其他自动化录入能力，必须同时满足以下边界：

1. 自动化只读取系统导出的财务填报草稿，不直接把 AI 识别结果当成最终提交事实。
2. 每次准备提交前，必须由管理员在系统内或自动化执行界面显式人工确认本次提交。
3. 自动化执行只允许辅助填表，不得默认自动点击最终提交按钮，除非产品需求、审计和回滚方案被单独批准。
4. 必须记录操作者、触发时间、目标任务、填报摘要和执行结果，保证审计可追溯。
5. 不在仓库或服务端长期保存财务系统明文凭据；若引入临时登录态，必须有明确失效和清理策略。
6. 一旦财务系统页面结构、规则或登录流程变化，自动化能力应失败显式暴露，而不是静默降级为“提交成功”。

在这些条件被单独设计、实现和验收之前，当前仓库应继续把 Browser Use 视为后续阶段能力，而不是第一阶段的隐藏需求。
